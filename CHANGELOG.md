# Changelog

## 0.4.0 — 2026-11-23

### Added

- Cross-platform graph lock: `fcntl.flock` on Unix, `msvcrt.locking` on
  Windows, behind `locking.file_lock`. `fg.py` no longer imports `fcntl`.
- `nvwa` is Python. The default runner (`NVWA_RUNNER=subprocess`) launches
  the backend CLI as a child process, logs to `.fg/agents/<name>.log`, and
  stores state in `.fg/agents/<name>.json`. Commands: `spawn`, `say`,
  `listen`, `ps` (`list`), `logs [-f]`, `stop` (`kill`), `board`.
- `NVWA_RUNNER=tmux` keeps pane-per-agent behavior where tmux exists.
- `nvwa ui` serves a loopback panel (stdlib `ThreadingHTTPServer`, default
  `127.0.0.1:8765`) with agent start/stop, SSE output, a say box, and the
  existing fact-graph view on a 2s refresh. A per-launch token is required
  on `/api/*`; a foreign `Origin` is rejected.
- API: `GET /api/agents`, `GET /api/graph`, `GET /api/agents/<name>/stream`,
  `POST /api/agents`, `POST /api/agents/<name>/say`,
  `POST /api/agents/<name>/stop`.
- GitHub Actions matrix: `ubuntu-latest` and `windows-latest`.

### Changed

- `fg-hook` reports local time from the stdlib instead of the `date` command,
  so the hook imports on Windows.
- `fgc init` allows an existing `.fg/agents/` directory.
- Opening a URL uses `webbrowser`; opening a file on Windows uses
  `os.startfile`.

## 0.3.0 — 2026-11-23

General-purpose fork. The fact graph, hooks, dispatch loop, HTML view, and
`nvwa` tmux runtime stay. Domain-specific framing does not.

### Removed

- Docs and roadmap items that described a penetration-testing legion,
  attack-defense scoring, and an offensive-tool marking scheme.
- Docs for an unimplemented pentest fact schema (`host` / `service` / `cred`
  / `vuln` / `loot` / `flag`, `-k` / `-d`). Facts remain untyped observations.
- The example that asked the commander to classify work as attack surface,
  payload, or exploit evidence.

### Added

- Selectable dispatch backends: `claude` (default), `codex` (OpenAI Codex CLI
  `codex exec --json`), and `grok` (xAI Grok CLI `grok --output-format json
  --prompt-file`). Choose with `--backend`, `FG_BACKEND`, or `NVWA_BACKEND`.
- `fgc backend` prints the resolved backend, model, binary, and whether an
  API key is configured. It does not print the key.
- Codex auth: `CODEX_API_KEY`, or `FG_CODEX_API_KEY` / `OPENAI_API_KEY` copied
  into the child environment as `CODEX_API_KEY`. Binary `FG_CODEX_BIN`, model
  `FG_CODEX_MODEL`.
- Grok auth: `XAI_API_KEY`, or `FG_GROK_API_KEY` copied to `XAI_API_KEY` when
  unset. Binary `FG_GROK_BIN`, model `FG_GROK_MODEL`.
- `nvwa spawn` follows the same backend when `NVWA_AGENT` is unset, and puts
  the API key in the tmux session environment rather than on the command line.

## 0.2.0 — 2026-09-24

This release hardens the graph at the boundaries where a local JSON file, an
LLM response, or a project settings file can be malformed or untrusted.

### Changed

- Added `fgc validate`, a read-only audit for node schemas, dangling fact and
  intent references, source links, duplicate filenames, and project completion
  state.
- Read commands now skip malformed node files with a warning so one damaged
  record does not take down `status`, `graph`, hooks, or the HTML view. The
  validator reports the skipped record so the damage is not hidden.
- Confirmation gates are enforced at claim and conclusion write boundaries.
  A `--confirm` intent must be explicitly confirmed before execution or
  completion; dry-run prompt inspection remains available.
- CLI node ids are validated before path construction, blocking `../` lookups.
  Fact source links are checked, and stale counters advance past occupied ids
  instead of overwriting restored nodes.
- Static graph snapshots escape `<`, `>`, and `&` before embedding JSON in a
  `<script>` block, so hostile graph text cannot close the script element.
- Initialization is locked, JSON writes use unique same-directory temporary
  files plus `os.replace`, and project settings are patched atomically.
- `fgc teardown` removes only an `AGENTS.md` generated by fgc; an existing user
  file is preserved and clearly reported.
- Brainstorm batch ids now include entropy, and model option/risk fields are
  type-checked and bounded. Failed `dispatch verify` calls now return a nonzero
  exit code for shell automation.
- `fgc fact --from-intent` now links and closes its source intent atomically,
  keeping the documented source edge consistent with `fgc validate`.
- Prompt placeholder replacement is now single-pass and graph summaries scrub
  control characters/backticks, so a fact containing `{goal}` cannot rewrite
  the template or spoof extra prompt rows.
- `fgc auto --verify` now surfaces failed checks and records a hint for the next
  reason step instead of silently treating an unverified fact as success.
- Setup validates an existing `.claude/settings.json` before creating `.fg/`,
  including hook event shapes, avoiding a half-configured project when
  Claude's settings are malformed.
- Peer configuration files are schema-checked before discovery, send, or
  capture uses them.

### Verification

The repository now includes a dependency-free `unittest` suite in
`tests/test_fg.py` covering corruption recovery, graph validation, confirmation
and ownership boundaries, path safety, stale counters, HTML script escaping,
brainstorm batch isolation, and settings patch preservation. Run:

```bash
python3 -m unittest discover -s tests -v
python3 -m py_compile lib/*.py
bash -n install.sh
git diff --check
```

### Investigation record

- The GitHub Issues, pull requests, and releases API for
  `N1nEmAn/claude-fact-graph` returned zero entries on 2026-09-24; the fixes
  therefore come from current-source review and reproducible local failures.
- The first reproduced failure was a fact file containing only `{"id":"f001"}`:
  `fgc graph` raised `KeyError: 'description'`. The new reader warning and
  `fgc validate` behavior are covered by a regression test.
- Python standard-library references consulted for the storage changes:
  [`tempfile.mkstemp`](https://docs.python.org/3/library/tempfile.html#tempfile.mkstemp),
  [`os.replace`](https://docs.python.org/3/library/os.html#os.replace), and
  [`fcntl.flock`](https://docs.python.org/3/library/fcntl.html#fcntl.flock).
